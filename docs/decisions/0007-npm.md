# ADR-0007: npm jako menedżer pakietów

- Status: przyjęta
- Data: 2026-10-09

## Kontekst

Repozytorium ma jeden `package.json`, więc przewaga ścisłości pnpm jest mała. Projekty natywne Capacitora odwołują się do ścieżek w `node_modules`.

## Decyzja

npm w wersji 11 lub nowszej (`engines` w `package.json`, `engine-strict=true` w `.npmrc`) i Node 24 (`.nvmrc`).

## Odrzucone opcje

- **pnpm** – szybszy i z bezpieczniejszymi ustawieniami domyślnymi, ale symlinki w `node_modules` bywają problemem dla pluginów Capacitora, a każda osoba musi go zainstalować.
- **yarn PnP, bun** – słabe wsparcie w tym stosie.

## Konsekwencje

npm 10 kończy instalację tego workspace błędem `Cannot read properties of null (reading 'edgesOut')`, stąd wymóg npm 11. npm 11 ostrzega o skryptach instalacyjnych niezatwierdzonych w `allowScripts`; zatwierdzenie ich to osobne zadanie (QA-12).

## Kiedy wrócić do decyzji

Gdy czas instalacji w CI staje się problemem albo Capacitor oficjalnie wspiera pnpm z domyślnym układem `node_modules`.
